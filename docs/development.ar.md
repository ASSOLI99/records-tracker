## بناء ملف APK مستقل محليًا (ويندوز)

</div>

```bash
npx expo prebuild --platform android
```

```bash
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a -Pexpo.useLegacyPackaging=true
```

<div dir="rtl">

يُكتب ملف APK في `android/app/build/outputs/apk/release/`.

- **حد طول المسار في ويندوز:** البناء الأصلي (CMake) في React Native يفشل مع مسارات أطول من ٢٦٠ حرفًا.
  1. ابنِ من مجلد قصير مثل `C:\rt`.
  2. إن فشل بناء الإصدار رغم ذلك، أضف
     `externalNativeBuild { cmake { buildStagingDirectory = file("C:/c") } }` داخل `android { }`
     في `android/app/build.gradle`.

  مجلد `android/` يُولَّد تلقائيًا، فأعد إضافة السطر بعد كل prebuild.
- الخيار `-Pexpo.useLegacyPackaging=true` يضغط المكتبات الأصلية (من نحو ٣١ ميغابايت إلى ١٧ ميغابايت
  لملف APK بمعمارية arm64).
- البناء المحلي للإصدار يُوقَّع بمفتاح التصحيح (debug key). هذا مناسب للتثبيت اليدوي، أما متجر Play
  فيحتاج مفتاح رفع وملف `.aab`.

## خريطة الكود

| المسار | المحتوى |
|---|---|
| `src/model/` | المنطق الصافي: الأنواع، فترات المحفّزات (`periods.ts`)، التقدم والسلاسل (`progress.ts`)، عناصر الرحلة، القوالب، العناوين |
| `src/storage/` | الوصول إلى المجلد (`fs.ts`، يدعم روابط منتقي المجلدات في أندرويد) وحفظ الخطط والملف الشخصي والمرفقات (`repo.ts`) |
| `src/state/app.tsx` | حالة التطبيق: مرحلة الإعداد، المجلد الجذر، الملف الشخصي، الخطط، اللغة |
| `src/i18n/` | نصوص العربية والإنجليزية، عزل الاتجاه، تنسيق التواريخ |
| `src/ui/` | مكونات الواجهة، المظاهر، اتجاه `useDir()`، النوافذ والحوارات، المنتقيات |
| `src/themes/` | المظاهر الستة، وكتالوج الأيقونات والبحث فيه |
| `src/components/` | منتقي المظهر، محررا المحفّزات والقوالب، عروض الرحلة، جزيرة الحالات، درج الأهداف، قائمة الدبوس |
| `src/app/` | المسارات (Expo Router): البداية، الرئيسية، عنّي، خطة جديدة، الرحلة، الخطوة، شاشات التعديل |
| `src/notifications.ts` | التذكيرات المحلية المبنية من المحفّز الحالي لكل خطة |
| `assets/fonts/` | خط Cairo بستة أوزان (SIL Open Font License، `Cairo-OFL.txt`) |

## قرارات التصميم

- **الاتجاه يتبع اللغة، لا علم RTL الأصلي.** الشاشات والنوافذ تضبط `direction` في Yoga من `useDir()`،
  فيُطبَّق تبديل اللغة فورًا. ويُحدَّث العلم الأصلي أيضًا لتطابق واجهة النظام بعد التشغيل التالي.
- **نصوص آمنة الاتجاه.** القيم المُدرجة تُحاط بعلامات العزل في Unicode، والجمل العربية التي فيها قيم
  مُدرجة تبدأ بعلامة «من اليمين إلى اليسار».
- **التخزين في أندرويد يستخدم Storage Access Framework.** الكتابة فيه لا تقص الملفات الموجودة بشكل
  موثوق، ولا يمكن إعادة تسمية الملفات، لذا يُكتب JSON دائمًا في ملفات جديدة: النسخة الاحتياطية أولًا ثم الرئيسية.
- **تغيير المحفّز يضيف مقطعًا يبدأ من «الآن».** وتغيير القالب يضيف نسخة جديدة منه. والخطوات المملوءة
  تحتفظ بنسخة من حقولها.

## المتاجر والإشعارات والودجت

- **Google Play:** جاهز كما هو. التطبيق لا يطلب أبدًا `MANAGE_EXTERNAL_STORAGE` أو `READ_MEDIA_*`،
  بل يستخدم منتقي المجلدات ومنتقي الصور في النظام، وهذه الأذونات محظورة في `app.json`. ملف الإصدار
  لا يحتوي أذونات تخزين أو وسائط أو عرض فوق التطبيقات. نموذج أمان البيانات: لا تُجمع بيانات ولا تُشارك.
- **App Store:** جاهز كما هو. لا يوجد إذن تخزين في iOS أصلًا، ومجلد Documents الظاهر في تطبيق الملفات
  هو الطريقة المعتمدة. نصوص استخدام الكاميرا والصور مضبوطة. تصنيف الخصوصية: *لا تُجمع بيانات*. ولا
  يوجد تسجيل دخول، فلا يمكن أن تتعطل المراجعة بسبب مشكلة دخول.
- **الإشعارات:** نعم، محلية بالكامل. لكل خطة حد أقصى ٢٠ إشعارًا مجدولًا، لأن iOS يسمح بـ ٦٤ لكل تطبيق.
- **الودجت:** ممكن لكنه غير مبني بعد. حزمة `expo-widgets` في SDK 58 تغطي ودجت الشاشة الرئيسية وشاشة
  القفل في iOS وودجت الشاشة الرئيسية في أندرويد. يحتاج نسخة تطوير و App Group، وسيرسل التطبيق السلسلة
  وتقدم اليوم إلى الودجت.
